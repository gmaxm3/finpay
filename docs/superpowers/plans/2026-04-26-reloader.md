# Stakater Reloader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy Stakater Reloader to all workload clusters and annotate every CDE/DMZ Deployment so that changes to Secrets or ConfigMaps automatically trigger a rolling restart.

**Architecture:** ArgoCD ApplicationSet in `infrastructure/reloader/` deploys the Reloader Helm chart (via Stakater's Helm repo) to five clusters: dev, test, stage, prod-dmz, prod-cde. Each Deployment in `k8s-ops/apps/cde/` and `k8s-ops/apps/dmz/` gets `reloader.stakater.com/auto: "true"` added to `metadata.annotations`. Reloader runs with `watchGlobally: true` so it can watch secrets in `*-cde` / `*-dmz` namespaces from its own `reloader` namespace.

**Tech Stack:** Stakater Reloader Helm chart (`stakater/reloader` ≥ 1.4.x), ArgoCD ApplicationSet, Kustomize, SOPS/age secrets.

- [ ] **Step 2: Create `infrastructure/reloader/applicationset.yaml`**

```yaml
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: reloader
  namespace: argocd
  labels:
    app.kubernetes.io/part-of: finpaybank
    app.kubernetes.io/name: reloader
spec:
  goTemplate: true
  goTemplateOptions: [missingkey=error]

  generators:
    - list:
        elements:
          - cluster: dev
            server: https://DEV_NODE_IP:6443
          - cluster: test
            server: https://10.201.34.10:6443
          - cluster: stage
            server: https://STAGE_NODE_VIP:6443
          - cluster: prod-dmz
            server: https://PROD_DMZ_VIP:6443
          - cluster: prod-cde
            server: https://PROD_CDE_VIP:6443

  template:
    metadata:
      name: "reloader-{{.cluster}}"
      namespace: argocd
      labels:
        app.kubernetes.io/part-of: finpaybank
        app.kubernetes.io/name: reloader
        environment: "{{.cluster}}"

    spec:
      project: default

      source:
        repoURL: https://stakater.github.io/stakater-charts
        chart: reloader
        targetRevision: "1.4.x"
        helm:
          values: |
            reloader:
              watchGlobally: true
              ignoreSecrets: false
              ignoreConfigMaps: false
              logFormat: json
              podAnnotations:
                cluster-autoscaler.kubernetes.io/safe-to-evict: "true"

      destination:
        server: "{{.server}}"
        namespace: reloader

      syncPolicy:
        automated:
          prune: true
          selfHeal: true
        syncOptions:
          - CreateNamespace=true
          - ServerSideApply=true
        retry:
          limit: 3
          backoff:
            duration: 10s
            factor: 2
            maxDuration: 3m
```

- [ ] **Step 2: Add annotation to DMZ template**

File: `k8s-ops/apps/dmz/_template/base/deployment.yaml`

The DMZ template already has `metadata.annotations`. Add the reloader annotation to the existing block:

```yaml
    metadata:
      labels:
        app.kubernetes.io/name: SERVICE_NAME
        ...
      annotations:
        # PCI-DSS: логувати всі зміни конфігурації
        kubectl.kubernetes.io/last-applied-configuration: ""
```

Note: The `annotations` in the DMZ template under `spec.template.metadata` is for pods, not the Deployment itself. The Deployment-level `metadata.annotations` block (top-level) is what Reloader reads. Add it there:

```yaml
metadata:
  name: SERVICE_NAME
  annotations:
    reloader.stakater.com/auto: "true"
  labels:
    app.kubernetes.io/name: SERVICE_NAME
    app.kubernetes.io/component: SERVICE_NAME
    app.kubernetes.io/part-of: finpaybank
    zone: dmz
```

```markdown
## Reloader (автоматичний рестарт при зміні секретів)

Stakater Reloader задеплоєний на всіх кластерах (`reloader` namespace). Всі CDE/DMZ Deployment мають анотацію:
```yaml
annotations:
  reloader.stakater.com/auto: "true"
```
При зміні будь-якого Secret або ConfigMap, на який посилається Deployment — Reloader автоматично ініціює rolling restart. Ручний `kubectl rollout restart` більше не потрібен після зміни `shared-secrets` або `*-config`.

Нові сервіси: анотація вже є в `_template/base/deployment.yaml`.
```
